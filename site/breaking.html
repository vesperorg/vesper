Breaking Vesper.

Every way Vesper can be traced, attacked, or let you down, as far as we know, in one place, with what fixes each and when. Monero's developers did this on camera and it is the most trust-building thing any coin has done. This page is updated with every release. If you find something missing, that is the bounty.

The register, as of node v0.9.1 (testnet-1), 28 October 2026

What an attacker can do today.

How to read it. Severity is how bad it is if it happens. How likely, today is whether anyone can actually do it to testnet-1 as it stands, and what they get. Already done is what is built and measured against it, so you can check the claim. Bigger network says whether more people running nodes and mining makes it harder, and how; where it says no, only code, an audit or your own care will.

The sender's crowd is 48. A payment's input hides among 48 outputs, three times Monero's ring. Thirty-second blocks collide. Two miners who find a block within the seconds it takes one to travel (longer over Tor) make competing branches; the shorter the block time, the more often, and collisions favour whoever has the most mining power. Testnet-1's first such split lasted three days because of a sync bug, since fixed; the collisions themselves are inherent.Who: large miners, slow linksmedium, being measuredCertain: two miners will sometimes find a block in the same seconds. More miners means more collisions, but no single miner's branch dominates and a split is settled in a block or two. What matters is that nobody holds most of the mining power.

Why more nodes and more miners make this harder, exactly. Three of the weaknesses above are about numbers, and numbers are the one thing a volunteer fixes just by showing up.
  • Rewriting history or blocking payments takes more proof-of-work tries per second than every honest miner put together, for as long as the attack lasts. Testnet-1 today is the seed's one core and the founder's PC: a few hundred tries a second. One laptop is a fifth of that. Ten laptops make the founder a minority, which is the point of asking. A thousand make the attack a data centre's electricity bill, and no single person's decision.
  • Naming who sent a payment from the network works about as often as the spy's share of the nodes: one spy among ten nodes gets about one payment in nine, one among a thousand gets one in a thousand. Each honest node shrinks the share, and nodes are cheap: a node does not need to mine.
  • Staying up without the seed is simply having other doors. Every node that keeps running is one; once a node has met a few peers it never needs the seed again.

What the crowd does not fix: everything marked "by design", the ledger's size, your wallet file, exchanges at the edges, and the quantum question. Those take code, an audit, and your own care, and this page says which.

What is not on this list, and why that matters. Receivers, amounts and (within a crowd of 48) senders are hidden, and nobody has shown otherwise. On testnet-1 nothing here is money: tVESP has no value, which is the point of breaking it there first. The self-test ships with a check named for what the chain still leaks; if a line above ever stops being true, that test and this page change together. "Untraceable" appears nowhere on these pages until stage two and an audit say it can.
Fixed already

Things that were true and no longer are.

2026-10-28
Fixed. Two things the wallet app's first test run turned up. A wallet reading the whole chain for the first time (about a hundred requests in a row) twice had a connection reset by its own node just after the miner started: the node's accept queue was 5, and Windows resets new connections when it is full. Now 64, and a reset read is retried once. And for about a minute after sending, your own node answered "no such transaction" for your own payment, because it was still on its quiet hand-off (the stem) and not yet in the public mempool. The node now shows a payment on its stem to its own computer only, marked as such; anyone else asking still gets nothing, so the stem stays private. Commit 748fd01.
2026-10-28
Fixed. Twenty-three rough edges found by reviewing what a first-time user actually sees. A wrong file path, a missing folder or a damaged wallet file dumped a stack trace (now one plain sentence). With Tor not running, the error blamed the node (now it asks "Is Tor running?"). A wrong password printed a balance of zero instead of an error. A typo in a wallet name silently created a new wallet. Pressing Enter at the password prompt saved an unencrypted wallet (now you must type NONE to mean it). Sending 0 was accepted up to the password prompt. A --config path that did not exist fell back to another coin's defaults. Payment proofs were written next to the code (now data/wallets/proofs/). Flags after the command were ignored. All in commit db5b836.
2026-10-27
Fixed. On testnet-1 the founder's home node and the seed found block 5,188 at the same moment. The home node, behind a router and later Tor, out-mined the seed on its own branch, but the seed could never reach it to fetch that branch, so the two stayed split for three days. A node with more work now hands its side of the chain to the peer itself, in checked batches of up to 100 blocks; a node no longer mines while it is catching up with a peer that is ahead, nor before it has asked its peers once; and a fork check that times out over Tor keeps its progress instead of starting over. Node v0.9.1.
2026-10-27
Fixed. The seed server's update script only started the node if it was stopped, so after an update a running seed kept the old code (it stayed on v0.9.0 after the v0.9.1 update). The script now restarts the node every time.
2026-10-27
Fixed. Two node processes started on one data folder damaged its chain file. One process per folder now (node.lock), and reset-chain refuses to run while a node is running.
2026-10-23
Fixed. Once the seed's address went into config.json, the self-test's peer-table check used the real seed list and failed, so the seed server's own update would have refused to restart the node. Self-test nodes now start with an empty peer list.
2026-10-21
Fixed. On a small rented server the service's memory cap was above the machine's RAM, and mining on the single core starved the node's web side so it stopped answering. Swap is added on machines under 3 GB, the cap is 85% of the machine, and mining runs at low priority so answering peers comes first.
2026-10-15
Fixed. The node had no connection timeout, so 64 idle connections (a "slowloris", a few lines of code) locked every peer and wallet out for as long as they stayed open. Now 20 s, at most 8 slots per address, and the node's own computer is never turned away.
2026-10-15
Fixed. Only the number of payments per block was limited, so a valid 18 MB block was possible that no node could relay or fetch, which would have split the network. Blocks are now at most 4,000,000 bytes, by consensus.
2026-10-15
Fixed. Every address a peer mentioned was trusted at once, so one attacker could fill a node's whole peer table (an "eclipse"), decide what it sees and be the first hop of every payment. Gossip is now candidates, checked two a round, at most 2 per network block.
2026-10-15
Fixed. Inputs were listed biggest coin first, so their order said which hidden input held more. Inputs are now listed in key-image order and blocks refuse any other order.
2026-10-15
Fixed. A wallet on another computer could tell from a fast "not new" answer that its payment was already on this node's stem. Every hand-in is now checked all the same and called new.
2026-10-15
Fixed. The first phase-4 build answered a stem it already held with "loop", so anyone holding a payment could ask every node and learn which nodes were on its stem, then trace it back: up to 38% of payments at 5% spies, worse than no stem at all. Found in review the day it was built, before any network ran it. Hand-offs are now answered at once and alike, duplicates dropped silently, loops end by timer.
2026-10-15
Fixed. Decoys were picked by rank in the output line, and an attacker who knows how people spend named the real coin 7.3% of the time on a young chain and 22% on a busy year-old one. Decoys are now drawn as ages from the measured spending distribution: 7.2%, 6.5%, 6.1% (fair 6.2%).
2026-10-15
Designed out. Subaddresses arrived with the Janus check: an output built from one of your addresses that lands on another (to learn both are yours if you confirm it) is refused, because the wallet re-derives the payment key from a sealed anchor. Monero's subaddresses still carry this one.
2026-10-15
Fixed. A node whose clock was behind treated its own newest saved blocks as "from the future" and set them aside as damaged at start. The future-time rule now applies only to blocks arriving from peers.
2026-10-14
Fixed. One changed character in the saved chain file stopped the node from starting. It now keeps the good blocks, sets the damaged file aside and fetches the rest from peers.
2026-10-11
Fixed. Any website open in your browser could stop your miner or redirect its rewards through the node's local API. The node now refuses cross-site requests. The same hole was found and closed in the learning chain.
2026-10-11
Fixed. Two different blocks could in principle share an ID (the Merkle-tree duplication flaw behind Bitcoin's CVE-2012-2459). Designed out; and a node now records a block only under an ID it computed itself, so a peer cannot delay a real block by sending junk under its ID.
2026-10-11
Fixed. Replacing a whole ring after a reorganisation removed one decoy leaked which output was real. Now only the lost decoy is replaced.
2026-10-11
Fixed. Two payments to the same one-time key used to share one spent marker, so only one could ever be spent (Monero's "burning bug"). Spent markers are now tied to each output's position, so both are spendable, and no key-uniqueness rule is needed: such a rule would let a stranger cancel a waiting payment.
2026-10-11
Fixed. Wallets downloaded every output on the chain to find their own. They now read only new blocks, so the cost of privacy stopped growing with the chain.
2026-10-11
Fixed. Proof of work was Bitcoin's SHA-256, so rented Bitcoin hashrate could overrun the chain in hours. Switched to memory-hard Argon2id.
2026-10-11
Fixed. Difficulty adjusted once every ten blocks, a known hash-and-run target for small chains. Now adjusts every block.
2026-10-11
Fixed. A power cut while saving a block could leave the chain file unreadable.
2026-10-11
Fixed. Spending a mining reward revealed that payment's total (public reward in, sealed outputs out). Rings removed the link to the spent output.
2026-10-10
Fixed. Amounts were visible on chain. Sealed with commitments and range proofs in phase 2.
Found one?

How to report, and what you get.

  1. Check this register and the whitepaper's threat model. If it is listed, it is known; tell us anyway if you can show it is worse than described.
  2. Write it up so we can reproduce it: what you saw, how, with what data. Chain file, transaction IDs, a script if you have one.
  3. Send it privately: open a GitHub issue in the repository titled "security: contact requested" with no details, and a private channel is arranged from there (the same route is in SECURITY.md). Public disclosure before a fix forfeits the bounty, never the credit.
  4. You are credited here by name or handle when the fix ships, and paid from the bounty pool according to severity, in public.

The bounty rules are on the Join page. This page is the only marketing a privacy coin should need: a list of its own flaws, kept honestly.
